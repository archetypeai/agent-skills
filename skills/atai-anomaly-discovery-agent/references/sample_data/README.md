# Sample data — one bearing crossing from normal into failure

`bearing_eval_set2_brg1_transition.csv` is 120 consecutive snapshots
(245,760 rows, 5.5 MB) from a bearing that ran to an **outer-race failure**,
taken from the middle of its life so that it spans the moment the detector's
score crosses the threshold.

| | |
|---|---|
| Source | NASA IMS Bearing Data Set, test 2, bearing 1 |
| Sampling | 20.48 kHz, 2,048 rows per snapshot, snapshots 10 minutes apart |
| Columns | `timestamp` (seconds, float), `vibration` (z-scored) |
| Span | 63.8 → 44.0 operating hours before end of record |
| Crossing | ~50 snapshots in |

**Why a transition slice rather than a tail.** A tail long enough to contain the
full 55.5-hour lead would be 17 MB. This is a quarter the size and shows the
part that matters: the score sitting near 1.0, then leaving.

**Why the values are z-scored.** The detector was fitted on z-scored input, so
that is its contract. One pooled `(mean, std)` per experiment, which preserves
every between-window amplitude ratio — Omega z-scores each window internally
anyway and passes the original `(mean, std)` to the model as a scale token, so a
second per-window normalization would flatten it.

`…_labels.csv` is the ground-truth sidecar: one row per window, carrying
`snapshot_index`, `operating_hours_to_end`, `in_reference`, `failed` and
`defect_mode`. The runner uses it for lead time only — **it never influences a
score**. Snapshot indices are renumbered from 0 so the file stands alone.

There is no per-window "is this anomalous" label here, and that is not an
omission: the dataset has none. See SKILL.md, "Scoring".
